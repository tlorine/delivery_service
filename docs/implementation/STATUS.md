## Сценарий MVP (раздел 11 ТЗ) — что проверено E2E в браузере
1–5. Сайт кафе → меню (SSR) → товар → добавки (обязательные/лимиты групп) → корзина (одинаковые конфигурации объединяются).
6–8. Контакты, доставка/самовывоз, адрес из подсказок с координатами; зона и стоимость доставки считаются сервером до оформления; адрес вне зоны — заказ невозможен.
9–11. Согласие на обработку ПДн, оформление; сервер пересчитывает цены, проверяет доступность, зону, минимум, расписание; заказ в PostgreSQL со снимком цен.
12. Уведомление в Telegram — проверено интеграционными тестами с фейковым Bot API и ручным запуском воркера (реальный бот не подключался).
13. Подтверждение сотрудником в админке — E2E: оператор видит новый заказ (звук, счётчик во вкладке), проводит его по статусам, покупатель видит каждый шаг; отклонение — только с причиной.
14. Покупатель видит текущий статус (страница заказа, автообновление).

## Что работает (backend)
- Тенант по Host / `X-Forwarded-Host` от прокси / `X-Tenant` (только на платформенном хосте) / членству сотрудника.
- Витрина, меню с модификаторами и стоп-листом, слоты времени, подсказки адреса (`Geocoder`: DaData / demo / none).
- Серверная корзина, расчёт цен только на сервере.
- Оформление: зоны (полигоны), мин. сумма, бесплатная доставка, расписание в часовом поясе филиала, заказ ко времени, способы оплаты, сдача, телефон, согласие на ПДн, `409 price_changed`.
- Идемпотентность, блокировки, последовательные номера — конкурентные тесты.
- FSM заказа, отмена покупателем, переходы сотрудником с причиной, аудит, история.
- Outbox + воркер (LISTEN/NOTIFY), повторы, `retry_after`; Telegram-уведомление кафе.
- Админ-API: вход, сессии, роли, CSRF, заказы. Изоляция тенантов: API, RLS, составные FK.

## Что работает (витрина)
- Сторы `core`/`web-app` переведены с BFF NextOrders на `packages/api-client`; BFF и Gateway удалены. Публичный интерфейс сторов сохранён — компоненты почти не менялись.
- Новое: выбор добавок, строки корзины с добавками, стоимость доставки и итог из серверного расчёта, согласие на ПДн, локализованные ошибки по `code`, страница статуса заказа с отменой.
- Русский язык по умолчанию; 9 неподдерживаемых локалей upstream — с откатом на английский.
- Удалён выбор «каналов» (городов) NextOrders — маркетплейс-паттерн.
- Исправлено в ходе E2E: потеря корзины после перезагрузки, сброс способа получения при гидратации, рассинхрон токена корзины, безымянные селекты (доступность).

## Что работает (админка)
- Вход, сессия в `HttpOnly`-cookie, выбор заведения при нескольких членствах, разделы по ролям (оператор / менеджер / владелец).
- Заказы: лента «Новые / В работе / Завершённые» с опросом 10 с и звуком, карточка заказа, кнопки только допустимых переходов, причина для отклонения/отмены, история.
- Меню: категории, товары с вариантами и ценами, группы добавок (обязательность, максимум), цены добавок, скрытие; заказанное нельзя удалить — только скрыть.
- Стоп-лист по филиалу одним переключателем; расписание (несколько интервалов в день, ночной режим), время приготовления/доставки, способы оплаты; стоимость/минимум/бесплатный порог зон доставки.
- Настройки заведения, оформление витрины (фирменный цвет с превью и автоконтрастом, обложка), статус Telegram и команда `/link` для чата сотрудников; сотрудники (добавить, роль, удалить — доступ закрывается сразу); аналитика «сегодня / 7 дней / топ-5» в часовом поясе кафе.
- Найдено и исправлено E2E-тестами: поле цены округляло введённые 135 ₽ до 140 ₽ (шаг поля); rate limit входа (подтвердил работу ограничения).

## Технический долг (явный)
| Долг | Почему допустимо сейчас | Когда закрыть |
|---|---|---|
| Rate limit в памяти процесса | один инстанс API | перед масштабированием |
| Координаты адреса от клиента | заказ подтверждает человек | до агрегаторов доставки |
| Нет ссылки на политику ПДн тенанта и версии текста согласия | пилот | до запуска пилота |
| Мин. сумма доставки не видна до ввода адреса (зависит от зоны) | сервер сообщает при вводе адреса | UX-итерация |
| Витрина показывает статус первого филиала, мультифилиальность — только точки самовывоза | пилот — один филиал | при втором филиале |
| Локально PostgreSQL 14, CI/prod — 17 | фич 15+ не используем | — |
| Docker-образы (backend, web-app, admin) не собирались локально — нет демона Docker | собираются в CI (`backend.yml`, `images.yml`); Dockerfile витрины и админки переписаны и ещё не проверены сборкой | первый прогон `images.yml` после push в `main` |
| CI-workflow не запускались (нет push) | проверено локально теми же командами | первый push |
| Каталог одноязычный | рынок РФ | по запросу |
| Пиксельные эталоны скриншотов витрины не сняты (нужен Linux-образ CI) | инварианты вёрстки проверяются E2E | при настройке CI |
| Блюдо открывается страницей, а не шторкой поверх каталога | тот же путь в два касания, SEO-страница нужна в любом случае | по результатам пилота |
| Админка только на русском, строки в шаблонах | рынок РФ | при выходе на другие рынки |
| Границы зон доставки редактирует поддержка (нет редактора на карте) | у пилота одна зона | при подключении нескольких кафе с разными зонами |
| Новые заказы в админке — опрос 10 с, не push | один инстанс API, малая нагрузка | вместе с брокером событий |
| `apps/essence` остаётся в репозитории | не используется; удаление — отдельная правка lockfile | при очистке upstream-наследия |
