## 2. Референс: что берём из UX Яндекс Еды (без бренда и графики)
По общеизвестным паттернам приложения (интерфейс не копируется, графика и бренд не используются):
1. Шапка заведения: название, статус работы, время и стоимость доставки; выбор «доставка / самовывоз» в начале пути.
2. Каталог одной лентой с липкой горизонтальной навигацией по категориям, подсветка активной при прокрутке.
3. Карточка: фото, цена крупно, название, вес; добавление прямо с карточки, после добавления — счётчик в карточке.
4. Блюдо — поверх каталога (bottom sheet на телефоне, модальное окно на десктопе), добавки — понятные списки с ценами, обязательные помечены; внизу закреплена кнопка «Добавить · сумма».
5. На телефоне — нижняя панель корзины «N · сумма» над контентом; на десктопе — компактная корзина справа, не колонка на всю высоту.
6. Прозрачная стоимость: товары, доставка, сколько осталось до бесплатной доставки / минимальной суммы.

Отличия (собственная идентичность): тёплая нейтральная палитра + акцент кафе из данных, шрифт Onest, мягкие крупные радиусы, «пилюли» категорий, своя форма карточек.

## 3. Дизайн-система витрины
- **Цвет:** нейтральная тёплая шкала (фон `#FAFAF7`, поверхности белые, текст `#1C1B19`, вторичный `#6B6862`, линии `#ECEAE4`). **Акцент** — из `branding.accent_color` тенанта (по умолчанию тёплый томатный `#D2381F` (4.85:1 с белым текстом, WCAG AA)); цвет текста на акценте выбирается автоматически по контрасту (WCAG ≥ 4.5:1). Семантика: успех, ошибка, предупреждение — отдельно от акцента.
- **Типографика:** один шрифт **Onest** (кириллица, OFL, самохостинг), шкала 12/14/16/18/22/28/34, вес 400/500/700; цифры цен — tabular.
- **Ритм:** шаг 4 px; поля страницы 16 (телефон) / 24 (планшет) / 32 (десктоп); радиусы: карточки 20, контролы 14, «пилюли» полные; тени — одна мягкая для «плавающих» элементов.
- **Состояния:** hover только как усиление (ничего не скрыто за hover), focus-visible кольцо акцентом, disabled — снижение контраста + причина рядом, нажатие — `scale(.98)`.
- **Брендинг данными:** `accent_color`, `logo_url`, `cover_url`, `description` в `tenant.branding` (поле уже отдаётся витрине как есть). Шрифт и формы — общие для платформы, чтобы шаурмичная, бургерная и кофейня выглядели законченно без дизайнера.
- Слой `packages/ui` используется и админкой: токены витрины живут в `apps/web-app`, админка не меняется.

## 4. Новая структура экранов
**Главная = каталог заведения** (одна страница):
1. Шапка заведения: обложка (если задана) или акцентная плашка с логотипом/инициалом; название, «Открыто до 23:00» / «Откроется завтра в 10:00»; строка условий «Доставка 40–60 мин · от 150 ₽ · бесплатно от 1 500 ₽».
2. Переключатель «Доставка / Самовывоз» (тот же стор).
3. Липкая полоса: поиск (иконка) + горизонтальные «пилюли» категорий со scroll-spy.
4. Секции категорий; сетка карточек: 2 колонки (телефон), 3 (планшет), 4 (десктоп без корзины) / 3 (десктоп с корзиной справа).
5. Страницы `/{category}` и `/{category}/{product}` сохраняются для SEO и прямых ссылок.

**Карточка блюда:** фото 4:3 со скруглением (если есть); без фото — карточка без пустой картинки: название крупнее, описание 2 строки, тонированная поверхность. Цена → название → вес. Кнопка «+» / «Добавить»: если у блюда один вариант и нет обязательных добавок — добавляет сразу и превращается в счётчик; иначе открывает блюдо.

**Блюдо:** на телефоне — шторка снизу поверх каталога (URL меняется, «назад» закрывает; в Telegram — BackButton), на десктопе/планшете — модальное окно; при прямом заходе — полноценная страница с той же композицией. Порядок: фото (max 45vh, без заглушки) → название, вес, описание → варианты (сегменты) → группы добавок (радио при max=1, чекбоксы/счётчики иначе; метка «обязательно», подсказка что выбрать) → закреплённая панель: счётчик количества + «Добавить · 470 ₽» (неактивна с понятной причиной).

**Корзина:**
- Телефон/планшет: нижняя панель «Корзина · 2 · 710 ₽» (в Telegram её роль играет MainButton) → экран корзины: строки (название, добавки одной строкой, цена, счётчик), подсказки «до минимальной суммы доставки / до бесплатной доставки», итог, кнопка «К оформлению».
- Десктоп ≥ 1280: компактная липкая карточка корзины справа (высота по содержимому), пустое состояние — одна строка текста.

**Оформление** — одна страница в порядке принятия решений: способ получения → адрес / пункт самовывоза → время → контакты → оплата (+ сдача) → комментарий → состав и итог (товары, доставка, к оплате) → согласие → закреплённая кнопка «Заказать · 1 090 ₽». Плейсхолдеры — примеры («+7 900 000-00-00», «Анна»).

**Статус заказа:** шкала этапов (принят → подтверждён → готовится → готов/в пути → выполнен), время, состав, кнопка отмены пока можно.

## 5. Адаптивность
Проверяемые ширины: 320, 360, 390, 430 (телефоны), 768, 820, 1024 (планшеты), 1280, 1440 (десктоп). Документ прокручивается целиком (без внутреннего скролл-контейнера), безопасные зоны `env(safe-area-inset-*)`, цели касания ≥ 44 px, без горизонтального скролла на всех ширинах.

## 6. Локализация
Русский по умолчанию; все новые строки — через словарь (`ru` и `en`); подвал без upstream-бренда; переключатель языка убран с витрины (язык — по браузеру, `ru` по умолчанию; механизм i18n сохранён).

## 7. Проверки
- Существующие E2E (50 сценариев) остаются; при изменении разметки сценарии адаптируются, но не ослабляются.
- Новые: инварианты вёрстки на 9 ширинах (нет горизонтального скролла; есть видимые цены/кнопки; панель корзины на телефоне; цели касания ≥ 44 px; текст не перекрывается изображениями), отсутствие латиницы в русском интерфейсе (кроме разрешённых слов), быстрое добавление с карточки, шторка блюда и «назад».
- Визуальные снимки `toHaveScreenshot` для ключевых экранов; эталоны снимаются в Linux (CI), локально — проверки инвариантов.

## 9. Открытые вопросы владельцу
1. **Фото блюд демо-кафе.** Случайные изображения не используем; без фото витрина показывает «текстовые» карточки. Для демонстрации нужны реальные фото кафе пилота (или лицензированные) — их можно задать через `image_url` в админке.
2. ~~**Акцентный цвет и обложка в админке.**~~ ✅ Сделано: «Настройки → Оформление витрины» — выбор цвета (палитра + HEX), превью кнопки ровно как на витрине (общая логика `packages/api-client/src/brand.ts`, с пометкой, если цвет затемнён для доступности), ссылка на обложку с превью, сброс к цветам платформы. Изменение API аддитивное: два необязательных поля в `Branding`.

**Отклонение от плана:** блюдо открывается **страницей**, а не шторкой поверх каталога. Причины: прямые ссылки и SEO всё равно требуют страницу; оверлей поверх маршрута в Nuxt заметно сложнее и хрупче; закреплённая панель действия даёт тот же короткий путь «выбрал → добавил». Вернуться к шторке можно позже без изменения API.

**Найдено и исправлено в ходе проверок:** кнопки, отрисованные сервером, до гидрации были «мёртвыми» (нажатие терялось) — теперь неактивны до готовности страницы; корзина дублировалась в DOM на телефоне (скрытая десктопная панель) — монтируется только на широком экране; мок Telegram снимал чужой обработчик MainButton — приведён к поведению Telegram; на одном экране один владелец MainButton.

**Визуальные снимки:** проверки вёрстки (ширины, видимость, размеры, язык) работают везде; пиксельные эталоны `toHaveScreenshot` зависят от шрифтового рендера ОС, поэтому их нужно снимать в Linux-образе CI (`--update-snapshots`) — не сделано, в техническом долге.
