# ADR-0001. Модульный монолит на FastAPI

Статус: принято · 2026-11-09

## Контекст
Один продукт, одна команда, пилот — одно кафе, цель — десятки/сотни заведений на одном экземпляре. Нагрузка небольшого кафе — единицы заказов в минуту в пике.

## Решение
Один Python-сервис `backend/` (FastAPI, SQLAlchemy 2 async, PostgreSQL), разделённый на модули по бизнес-границам (`app/modules/*`). Один Docker-образ, два процесса: `api` (uvicorn) и `worker` (outbox). Модули общаются через сервисы и события outbox, не через HTTP.

## Альтернативы
- **Микросервисы** — сетевые вызовы, распределённые транзакции, отдельный деплой каждого — без измеримой выгоды на этом масштабе.
- **Оставить essence (Nuxt/Nitro) как бэкенд** — in-memory, без БД, автор помечает «not for production»; TS-бэкенд противоречит выбранному стеку.

## Последствия
- Все инварианты заказа проверяются в одной транзакции PostgreSQL.
- Модуль можно вынести в сервис позже: границы — сервисные интерфейсы и outbox-события.
- Правило импорта: модуль меняет только свои таблицы; чужие — через сервис-владелец.
