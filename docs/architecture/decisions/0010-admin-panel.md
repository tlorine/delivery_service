# ADR-0010. Админка — отдельное Nuxt SPA на общем API

Статус: принято · 2026-11-09

## Решение
- `apps/admin` — Nuxt 4, `ssr: false`, расширяет только `@nextorders/ui` (тема, компоненты Nuxt UI). Слой `core` витрины не подключается: у админки нет корзины, Telegram-адаптера и SEO.
- Тот же API (`/v1/admin/*`) и тот же `@delivery/api-client`, что у витрины. `/v1/*` проксируется тем же сквозным middleware `packages/core/server/middleware/api-proxy.ts` (подключён через `serverHandlers`, не копируется) — админка работает с API на одном origin, поэтому сессия — `HttpOnly`-cookie без CORS (ADR-0009). Выбранное заведение — `X-Tenant-Id`, сервер проверяет членство.
- Роли проверяет сервер на каждом эндпоинте; клиент лишь скрывает недоступные разделы и перенаправляет (`definePageMeta({ role })`).
- Интерфейс — только на русском (MVP для РФ). Деньги вводятся в рублях и переводятся в копейки в одном месте (`utils/money.ts`, `rublesToMinor`); у числовых полей цен отключено округление к шагу.
- Состояние — `useState`, без Pinia: сессия и выбранное заведение — вся глобальная информация.
- Новые заказы: опрос каждые 10 с, звуковой сигнал (WebAudio, без файлов) и счётчик в заголовке вкладки. WebSocket/SSE — когда появится второй инстанс API или требования к задержке (вместе с брокером событий, ADR-0006).

## Не делаем в MVP
Редактор границ зон на карте (границы задаёт поддержка платформы через API/CLI; владелец меняет стоимость, минимум и порог бесплатной доставки), загрузку изображений (ссылка `https://`), отчёты сложнее «сегодня / 7 дней / топ-5».

## Последствия
- Второе кафе получает админку без отдельного деплоя: вход тем же адресом, выбор заведения — по членству.
- Перевод админки на другие языки потребует вынести строки (сейчас — `utils/labels.ts` и шаблоны).
